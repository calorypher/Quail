# M05.5 Results — Developer Agent Tooling v2

## Status

**PASS — ready for independent QA.** M05.5 adds bounded, provider-neutral repository tooling only. No Quail product source, product behavior, index/search semantics, packaging, CI/CD, or release behavior changed.

## Final public interfaces

```powershell
.\scripts\agent-preflight.ps1 -ExpectedBranch main -RequireClean -RequireCurrentOrigin -CheckTools

.\scripts\vm-verify.ps1 `
  -VmUser <lab-user> `
  -ArtifactPath <repository-relative-file>[,<repository-relative-file>...] `
  [-VmName Quail-Lab] [-Scenario CliStatus] `
  [-DataVolumeLabel QUAIL_LAB_DATA] [-RemoteRoot C:/Temp/Quail-M04.5] `
  [-TimeoutSeconds 90]

.\scripts\prepare-milestone.ps1 `
  -Milestone <identifier> -BranchName <new-branch> `
  -VmUser <lab-user> -VmRepositoryPath <explicit-remote-repo-path> `
  [-CheckpointName <identifier-clean>] [-VmName Quail-Lab] `
  [-DataVolumeLabel QUAIL_LAB_DATA] [-TimeoutSeconds 90] [-WhatIf]
```

`ArtifactPath` remains compatible with a single file. For `CliStatus`, the first artifact is the executable; later artifacts are deployed and integrity-checked too. All values must resolve to leaf files below the repository root, and duplicate remote basenames are rejected.

`prepare-milestone.ps1 -WhatIf` performs non-mutating guard validation (including read-only `ls-remote` freshness checks) and reports the checkpoint/branch it would create. A normal invocation may switch clean repositories to `main`, fast-forward only, create exactly one new checkpoint after all guards, then create the requested host branch. It never stashes, resets, cleans, rebases, force-pushes, restores, deletes, renames, or overwrites a checkpoint.

## Security and lifecycle behavior

The private `scripts/Private.QuailLab.psm1` is intentionally not a public entry point. It starts only an `Off` VM; a `Running` VM is left running. It then polls dynamic IPv4 addresses and SSH until the bounded timeout, recording retries only in `.quail-tooling/`.

All canonical SSH probe, remote PowerShell, and SCP calls use the same `HostKeyAlias=<VmName>`, dedicated ignored `.quail-tooling/quail-lab-known_hosts`, and `StrictHostKeyChecking=accept-new` options. First use records one key under the stable alias. Later address changes continue against that alias without a new trust prompt. A mismatched key is rejected by OpenSSH; no `ssh-keygen -R`, key replacement, null known-hosts database, or disabled host checking is used.

## Limitations and deferred work

- The real VM was already running; it was not stopped for an artificial `Off` test.
- Live creation of a disposable checkpoint was deliberately deferred; deletion remains safety-gated, and `-WhatIf` plus all checkpoint guards are available for QA before first M06 use.
- A live DHCP address change was not forced; stable-alias behavior is proven by canonical repeated calls and option review.
- Physical-host benchmark automation remains a deferred candidate. M06 should first establish whether its release-quality measurements repeat with a stable bounded contract.
- No general VM manager, SSH manager, remote executor, artifact synchronizer, fixture framework, installer, or Git publication automation was added.
