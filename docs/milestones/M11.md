# M11 — Real File Search integration

## Goal

Connect the production Quick Search window to the verified Quail 0.1 persistent file-search core while preserving the resident M10 desktop lifecycle.

## Scope

- Direct `Quail.App` reference to `Quail.Core`.
- Repeated temporary `Quail.exe --index <database-path>` startup arguments.
- Literal file-name search through `MultiIndexSearch` with its existing global limit of 50 and deterministic ordering.
- A small file-specific presentation model, background latest-query-wins coordination, real Shell type icons, keyboard selection, and Enter-to-open.
- Clear empty, no-index, searching, zero-result, search-error, and open-error states.
- Release/self-contained, Core/App-logic, real controlled-index, and short lifecycle/resource verification.

## Out of scope

M11 does not add an index catalog, index-management UI, build/sync/elevation workflows, a service, IPC/RPC, additional providers, path/fuzzy/ranked/content search, installer/updater work, or a generic plugin/result framework. Those remain future work, principally M12 and M13.

## Architecture boundary

The dependency direction is `WinUI -> Quail.App presentation/coordinator -> Quail.Core`. `Quail.Core` remains free of WinUI. The M10 named pipe remains test instrumentation only; it is not used for production search.

## Temporary index mechanism

`--index` is repeatable and normalized to a full path in input order. With no index the resident shell still starts, but a non-empty query displays `No file indexes configured.` There is no discovery, registry configuration, catalog, or automatic build/sync.

## Async and icon strategy

One background coordinator holds at most one pending request while synchronous Core search is active. A newer pending query replaces the previous one, generations preserve latest-query-wins, and only the latest current completion is applied on the UI dispatcher. Hiding the overlay or clearing the query invalidates prior completions.

Search text is shown before icon work. Shell icons are retrieved asynchronously using `SHGetFileInfo` with `SHGFI_USEFILEATTRIBUTES`, keyed by folder or extension, and retained in a bounded 128-entry LRU cache. Native `HICON` handles are destroyed after PNG conversion. The existing glyph remains as a fallback when retrieval is unavailable.

## Acceptance criteria

The production app must use real Core results, preserve its ordering/limit and fail-closed multi-index behavior, remain responsive during typing, avoid stale-result overwrite, open the selected indexed entry through `IndexedEntryOpener`, and preserve the M10 resident lifecycle and self-contained payload.

## Verification plan

Run the Core/App-logic suite, Release build, self-contained publish payload checks, no-index startup, and a real compatible persistent controlled index containing actual host files. Exercise query, rapid typing, selection, Enter-to-open, and a short lifecycle/resource run through the existing harness. Record compact durable summaries only.

## Stop conditions

Stop rather than expand scope if the integration needs Core search-semantic/schema changes, a persistent catalog, service/IPC/elevation, a new icon framework, material resource growth, or an M10 lifecycle regression requiring broad debugging.
