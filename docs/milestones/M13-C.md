# M13-C — Production packaging and 0.1 to 0.2 upgrade

## Goal

Produce the Quail 0.2 production Inno Setup installer and prove clean install, same-version reinstall, uninstall, and in-place upgrade from the real Quail 0.1.0 release.

## Scope

- Publish the normal unpackaged WinUI `Quail.exe` and `Quail.Cli.exe` for Windows 11 x64 as one framework-dependent installer payload.
- Use shared .NET 10 Desktop Runtime, Windows App Runtime matching the production Windows App SDK, and VC++ x64 Runtime. Detect only genuinely missing or insufficient prerequisites, download only missing prerequisites from pinned official Microsoft URLs, SHA-256 verify them before execution, and fail before application files are copied when bootstrap fails.
- Retain the stable Quail Inno Setup AppId, system PATH CLI contract, and installer-owned `Program Files\\Quail` directory. Add a Start Menu entry for the GUI.
- Prove safe cleanup of obsolete self-contained 0.1 application files during an in-place upgrade without deleting user configuration or index data outside `{app}`.
- Record aggregate durable evidence for payload identity, prerequisite decisions, all required installer scenarios, file counts/sizes, hashes, and disposition.

## Out of scope

M13-D technical RC measurements and lifecycle campaign; search or ranking changes; Windows Service work; updater work; MSIX/MSI/winget/Store packaging; trimming, Native AOT, single-file deployment; code signing; tag/release/publication; repository visibility changes; and destructive runtime removal from the physical host or Quail-Lab.

## Acceptance criteria

The real 0.2 GUI and CLI payload is framework-dependent, complete for supported unpackaged WinUI deployment, installed by Inno Setup with the existing product identity, and validated for prerequisite-present/offline, naturally missing prerequisites, reinstall, real 0.1.0 upgrade, obsolete payload cleanup, and uninstall/data preservation. Release tests and warning-free App/CLI builds pass. A result record must state either `ready for M13-D` or `packaging decision required`.

## Stop conditions

Stop for a decision if the real 0.1.0 baseline is not identifiable, production framework-dependent WinUI deployment requires a material architecture change or unsupported hack, prerequisite bootstrap cannot use verifiable official artifacts, safe obsolete-file cleanup reaches outside installer-owned `{app}`, a data migration is required, or a required missing-runtime scenario would require destructive runtime removal.
