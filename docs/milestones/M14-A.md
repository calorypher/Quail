# M14-A — Restarted public-release readiness audit

## Status

**Stopped — remediation required.**

This restarted audit applies only to `calorypher/Quail-public-staging`. The
private `calorypher/Quail` repository is a reference-only development archive
and is not part of the intended public surface.

## Baseline

- staging `main`: `62bbf3851e64c02af5b6856ff2d513bf05c607af`;
- staging tree: `26bf068c982422e4c85d4727218fe260c5e730d1`;
- one parentless root commit and 222 tracked files;
- one remote branch (`main`), zero tags, zero GitHub Releases, and zero legacy
  pull requests at audit entry;
- repository visibility: private.

## Goal

Determine whether Quail 0.2 and its intended public repository can proceed to
publication freeze as an MIT project without a secret/private-data blocker,
license incompatibility, unresolved high-impact security defect, unclear
redistributed-asset provenance, or misleading public documentation.

## Scope

The audit covers the complete reachable staging history and public GitHub
surface, production dependency and payload licensing, prerequisites and
installer licensing, repository license/notices, bundled and system-provided
assets, the privileged indexing boundary, installer/bootstrap behavior,
publication-facing documentation, unsigned-binary disclosure, naming and
metadata checklists, and the final Release build/installer gates.

The audit does not publish the repository, create a tag or Release, upload a
release asset, add product features, implement signing or an updater, migrate
legacy history, rewrite history, or modify the private archive.

## Stop condition reached

The focused installer review found that the elevated installer accepts a
caller-selected application directory while `[InstallDelete]` recursively
deletes every child of `{app}` before payload copy. Selecting or supplying an
existing non-Quail directory can therefore delete unrelated data with
administrator privileges.

This is a high-impact packaging defect that requires a production packaging
change and focused lifecycle revalidation. M14-A must stop with
`remediation required`; it must not silently redesign the installer or claim a
new technical release candidate.
