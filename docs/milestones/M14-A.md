## Goal

## Scope

The rerun starts the history/privacy, source-built artifact, SourceLink,

source. Previous M14-A evidence is historical input only. M14-I and M14-P

The audit does not publish or rename the repository, change visibility, create
a tag or GitHub Release, upload an asset, rewrite history, delete branches,
modify the private archive, purchase signing, or perform the final trademark
clearance gate.

## Historical stop condition (resolved by M14-T)

The installer accepts an empty or nonexistent custom destination without
validating that its ACL and ownership are suitable for a per-machine
installation. It later appends that destination to the machine `PATH` while
running with administrator privileges.

An empty custom directory can therefore be writable by an unprivileged user
and still become a persistent machine-wide executable search path. This is an
untrusted-path execution / local privilege boundary defect. Inno Setup's
enabled `RedirectionGuard` mitigates unprivileged junction traversal, but it
does not make a legitimate user-writable directory administrator-owned and
does not protect the resulting machine `PATH` entry.

M14-I's exact cleanup and ownership-recognition remediation remained present,
but the custom-destination policy left a separate trust problem.

M14-T replaced that policy with the fixed `{autopf}\\Quail` contract and passed
its focused T1-T10 validation. M14-A finalization records the current
disposition, licensing/notices, public documentation, and a new committed-source
technical candidate in [M14-A results](M14-A-results.md).
