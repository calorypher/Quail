# M14-I — Installer cleanup safety remediation

## Goal

Remediate the M14-A installer cleanup finding so an elevated Quail setup cannot recursively remove arbitrary contents of a selected installation directory. Validate the installer lifecycle without reopening the unrelated M14-A release-readiness gates.

## Scope

- remove the blanket installation-directory delete operation;
- fail closed before payload mutation when a non-empty destination is not a recognized Quail installation;
- retain upgrade, reinstall, uninstall, default directory, custom directory, PATH, shortcut, and data-preservation behavior;
- remove only an exact, evidence-derived set of obsolete Quail 0.1 self-contained files during a recognized upgrade;
- add focused static regression checks and execute focused Quail-Lab lifecycle validation;
- establish a replacement packaging technical RC while proving byte identity of the application payload against M13-D.

## Out of scope

- all remaining M14-A publication/readiness gates;
- application source or package changes;
- prerequisite contract changes or missing-prerequisite reconstruction;
- dependency, license, trademark, repository-visibility, release, or tagging work;
- changes to the private legacy archive.

## Acceptance criteria

- no full-tree deletion based solely on `{app}`;
- unowned non-empty default and custom destinations fail closed for interactive and silent flows;
- recognized Quail upgrades and reinstalls preserve foreign files;
- the exact obsolete Quail 0.1 self-contained runtime set is removed without a wildcard tree wipe;
- the focused lifecycle matrix T1–T9 passes on Quail-Lab using one hash-verified installer candidate;
- application payload remains byte-identical to the M13-D payload;
- no publication-sensitive action occurs.

## Verification plan

Run focused static packaging checks, Release tests/builds, canonical installer/payload/prerequisite guards, source review of the ownership policy, and the T1–T9 Quail-Lab lifecycle matrix. Record all identities and results in `M14-I-results.md` and focused evidence.

## Stop conditions

Stop with `remediation blocked` if safe ownership recognition needs a material packaging redesign, the exact legacy cleanup set cannot be established, the application payload changes unexpectedly, the lab cannot be used without unauthorized checkpoint/destructive normalization, or a material bypass remains after focused review.
