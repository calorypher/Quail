# M14-P — Public build provenance and privacy remediation

## Status

**Complete — public build provenance/privacy remediated.**

## Goal

Make the canonical Quail Release build independent of its physical checkout and
developer profile, while preserving the source-derived installer contract:

```text
exact public source commit -> canonical build -> release payload
```

## Scope

- diagnose Release PE, portable PDB, compiler, generated WinUI, MSBuild, and
  environment provenance before changing the build contract;
- map physical Release compiler paths to stable neutral virtual paths using
  supported .NET/MSBuild compiler configuration;
- guard the assembled Release payload against reintroduction of the current
  checkout or user-profile roots;
- build and compare the same source from two independent physical roots;
- validate privacy, canonical installer provenance, and focused runtime
  behavior without changing application semantics or installer ownership
  behavior.

## Out of scope

- resuming the full M14-A audit;
- changing application features, XAML, package versions, runtime configuration,
  prerequisite pins, or the M14-I installer ownership policy;
- changing the established PDB packaging policy;
- public release, repository visibility, tagging, asset upload, or changes to
  the private archive.

## Acceptance criteria

- Release payloads contain no physical checkout root, local account/profile,
  private identity, private archive, private email, hostname, or other
  host-sensitive provenance;
- the canonical installer build applies the privacy-safe contract automatically;
- two different clean checkout locations of one exact source commit are
  privacy-safe and reproducible, or any remaining byte difference is fully
  explained and benign;
- Release tests/builds and installer, prerequisite, payload, Windows App
  Runtime, and M14-I cleanup guards pass;
- the source-derived installer candidate and payload identities are recorded
  without publication-sensitive actions.
