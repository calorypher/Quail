# M21 — Unified Settings & Launch on Startup

## Status

**IMPLEMENTATION VERIFICATION PASS — ready for independent QA.**

## Goal

Replace the embedded Quick Search settings surface and separate user-facing Index Manager with one standalone Settings window for General, Indexing, and About. Add a simple per-user launch-on-startup setting for the installed desktop application.

## Scope

- one resizable WinUI Settings window, activated when Settings is requested again;
- General settings for launch on startup, Quick Search hotkey, and theme while preserving `%LOCALAPPDATA%\Quail\settings.json`;
- per-user startup registration in `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` under the owned `Quail` value, using the quoted installed `C:\Program Files\Quail\Quail.exe` command without `--show-on-start`;
- Indexing inside Settings, retaining the M20 sole-writer service, protected machine state, per-user `EnabledForSearch`, and existing bounded administrator control flow;
- concise product health mapping and recovery-focused rebuild actions;
- About information from assembly metadata plus repository and MIT license links;
- focused deterministic tests, Release test/build verification, and a bounded installer/lab check only when installer behavior changes.

## Out of scope

M22 Full Search, M23 Quick Search polish, M24 stabilization, search/ranking or storage changes, maintenance-service or IPC changes, automatic rebuild, updater, MSIX, telemetry, localization, content or additional sources, provider/settings frameworks, and broad multi-user deployment support.

## Acceptance criteria

- Settings is a single standalone window with General, Indexing, and About; closing it does not exit Quail and Exit closes it.
- Existing hotkey/theme and invalid-settings fallback behavior remain intact.
- Startup registration is the real owned HKCU Run value, is correctly quoted, has no `--show-on-start`, and is never created for a development output path.
- Indexing retains M20 semantics: Enable/Disable is per-user and unelevated; Build/Rebuild/Unregister use the existing administrator flow; Remove follows successful Unregister; healthy indexes do not present Rebuild as routine freshness work.
- About uses assembly version metadata rather than a duplicated UI version.
- `Quail.Core` gains no `Quail.FileSystem` dependency and no provider/settings framework is introduced.

## Verification

Run focused startup/settings/index-action tests, full Release tests and build, and `git diff --check`. If the installer changes, build it once and verify owned Run-value cleanup on Quail-Lab without removing M20 protected data. User-owned visual Settings and real sign-out/login smoke remain a required final acceptance check and may be pending at PR handoff.

## Stop conditions

Stop if the base, host/VM/checkpoint state, or worktree is unsafe; startup requires a service, MSIX, or a broader deployment architecture; M20 privilege/storage/service boundaries must change; a provider/settings framework or M23-level Quick Search redesign is required; or verification requires unbounded desktop automation debugging.
