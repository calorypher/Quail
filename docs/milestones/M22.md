# M22 — Full Search v1

## Status

**COMPLETE — independent QA and user acceptance PASS; ready for merge subject to explicit user approval**

M22 is the filesystem-only persistent result-browser milestone for Quail 0.3. It adds a second search surface without adding a second search engine or changing the M20 maintenance boundary.

## Goal

Add a normal persistent, resizable Full Search window for workflows that exceed the transient Quick Search result list. Quick Search and Full Search must use the same source-neutral App-to-Core search service and FileSystem source implementation.

## Architecture

Preserve the M15 dependency direction:

```text
Quail.App ---------> Quail.Core
                         ^
                         |
Quail.FileSystem -------+
```

`Quail.Core` must not reference `Quail.FileSystem`. Full Search must not call `IndexStore.Search` directly or implement independent query/ranking behavior. Extend the existing Core contracts only with a small typed opaque-details seam needed to pass source-specific request criteria and structured result values. Filesystem properties and actions remain optional and source-owned; a basic fake/non-filesystem source must continue to work without them.

Reuse the App-local `LatestSearchCoordinator` for Full Search. Do not perform the approved post-0.3 coordinator extraction unless a very small extraction is required to avoid direct M22 duplication.

## Scope

### Window and transitions

- Add one application-owned `FullSearchWindow` with normal native title bar, minimize, maximize, close, resizing, sensible initial size, and a minimum usable size.
- Apply the current Quail Light, Dark, or System theme and existing Windows-native resources.
- Add an outward-arrows Expand button immediately beside Settings in Quick Search, with `Open Full Search` tooltip.
- Expand transfers the current query, dismisses Quick Search, and activates or restores the singleton Full Search window.
- Add an inward-arrows Collapse button at the right edge of the Full Search header, visually adjacent to the native caption area without implementing broad custom chrome.
- Collapse transfers the current query, dismisses Full Search, summons Quick Search, and focuses its query field.
- Native Full Search close dismisses only Full Search. It must not summon Quick Search.
- Preserve the M21 `Alt+Space` Quick Search contract and do not add live two-way query synchronization.

### Search and result presentation

- Use a bounded Full Search limit of 1,000 results while preserving the smaller Quick Search limit.
- Present Name, Path/context, Kind, Size, and Modified date/time as structured values rather than parsing Quick Search display strings.
- Do not add Created metadata, schema, acquisition, filtering, or live-filesystem stat behavior.
- Use a virtualizing standard WinUI list/table presentation; do not add a third-party DataGrid or materialize thousands of heavy row controls.
- Show useful empty-query, no-results, no-source, transient maintenance, and real-error states without exposing stack traces or internal maintenance tokens.
- Preserve M21 searchability through transient maintenance unavailability; only existing proven invalid states remove a source.

### Sorting

- Default to existing M18 Relevance ordering.
- Support Name, Path, Size, and Modified ascending and descending, with an obvious return to Relevance.
- Define deterministic null and tie behavior and apply ordering and the final limit globally across all active filesystem indexes.
- Do not change Quick Search relevance semantics.

### Filters

- Type: All, Files, Folders.
- Extension: case-insensitive, optional, with or without a leading dot.
- Inclusive optional minimum and maximum size using a human-readable NumberBox plus KB/MB/GB units. Invalid minimum greater than maximum is a UI validation state, not a leaked search exception.
- Inclusive optional Modified From/To calendar dates. Each local date maps to the UTC FILETIME boundary for the start of that day and the last representable instant before the following local day, using the selected local time zone and correct DST rules.
- Optional required Hidden, System, and Read-only attributes; unchecked means no restriction.
- Keep the area compact and avoid a visual query language, expression parser, or capability framework.

### Actions and keyboard

- Open using Enter, double-click, and context menu.
- Reveal files in Explorer with selection where the normal Windows shell path permits; for folders, open the containing parent context.
- Copy the full indexed path using Ctrl+C and context menu.
- Keep result action routing opaque and source-owned without a global action registry.
- Preserve normal query editing. Standard list navigation must support Up/Down, PageUp/PageDown, Home/End, and context-menu access through standard Windows behavior.

### Search lifecycle

- Latest query/request wins; obsolete completions cannot overwrite newer UI state.
- Empty queries perform no search.
- Source changes invalidate stale requests and cannot crash the surface.
- Dismissed/closed Full Search cannot apply late results.
- Reuse existing scheduling; do not add new workers, thread abstractions, or a scheduler framework. Quick Search retains interactive priority.

## Out of scope

- Created metadata/schema/filtering;
- content indexing or additional sources;
- per-user indexing, FileSystemWatcher, deployment, installer, service, or protected-storage changes;
- public/dynamic plugins, provider SDKs, capability matrices, universal schemas, or lifecycle frameworks;
- boolean query trees, visual query builders, saved searches, tabs, previews, or relationship/history panes;
- rename, delete, move, copy-file, or multi-pane file-manager workflows;
- the full post-0.3 frontend extraction;
- updater work, M23 polish/animation, or M24 release-candidate work.

## Automated verification

Focused deterministic tests must cover:

- the shared Core service request path, unchanged Core/FileSystem dependency direction, optional filesystem details for fake sources, and bounded opaque action routing;
- every type, extension, size, modified-date, and attribute filter, including combined and nullable-metadata cases and invalid ranges;
- local calendar-date conversion, inclusive-day semantics, and a deterministic DST-sensitive time zone;
- Relevance and Name/Path/Size/Modified ascending/descending ordering, null policy, deterministic ties, and global multi-index ordering/limit;
- Quick-to-Full and Full-to-Quick query transfer, singleton activation, close-versus-collapse policy, stale-result suppression, empty query, and no-source mapping through pure policy/helper logic where practical.

Final regression verification must include focused M22 tests, the full Release suite, Release `Quail.App` win-x64 build, `git diff --check`, dependency-direction inspection, changed-C# readability inspection, and the small canonical M17/M18 relevance/performance guards affected by the search contracts. Do not repeat historical installer/service/reboot campaigns because M22 does not change those boundaries.

## Runtime and manual verification

Perform a bounded development-runtime startup smoke when available without adding desktop automation infrastructure. Ordinary visual Full Search acceptance may remain user-owned at implementation handoff.

The user-owned manual gate is:

1. Open Quick Search with `Alt+Space`, enter a known query, and verify outward Expand beside Settings.
2. Expand and verify Quick Search hides, Full Search opens with the same query, and repeated Expand does not create another window.
3. Verify resizing, minimize, maximize/restore, native close, and inward Collapse at the upper right.
4. Collapse and verify Full Search hides, Quick Search returns with the same query and query focus.
5. Close Full Search with X and verify Quick Search is not summoned.
6. On a large query, verify scrolling, all five fields, Relevance, Name, Size, and Modified sorts.
7. Verify Files, extension, size, modified-date, and one available advanced-attribute filter.
8. Verify Up/Down, Enter, Ctrl+C, Open, Reveal, Copy path, empty query, no-results, and current-theme presentation; optionally spot-check Light/Dark.

## Acceptance criteria

M22 is ready for independent QA when the window/lifecycle, shared Core path, bounded 1,000-result set, structured fields, deterministic sorting, all approved filters, global multi-index behavior, actions, keyboard behavior, states, focused/full tests, Release build, relevance/performance guards, dependency checks, and diff checks pass. Created remains deliberately absent, no speculative framework is introduced, and the branch/PR is ready for review. User-owned manual UI smoke may remain pending.

M22 must remain ACTIVE until independent QA and user acceptance are complete.

## Stop conditions

Stop rather than expand scope if M22 requires a Created-only schema/rebuild, a new filesystem backend, per-user indexing, maintenance/service ownership changes, `Core -> FileSystem`, a generalized filter/provider/capability or dynamic-plugin architecture, broad coordinator extraction, a third-party DataGrid, broad custom title-bar subsystem, new installer/deployment architecture, destructive repository/checkpoint repair, or an unbounded Quick Search relevance/performance regression.

## Completion boundary

End with a verified commit on `codex/m22-full-search-v1`, push it, and open a PR to `main` with exact evidence. Do not merge, delete branches, rewrite history, create or move tags, publish a release, or start M23/M24.
