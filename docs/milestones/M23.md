# M23 — Quick Search & UI Polish

## Status

**ACTIVE — implementation and verification are in progress on `codex/m23-ui-polish`.**

## Goal

Polish the integrated Quail 0.3 UI so Quick Search remains a fast, compact,
keyboard-first overlay while Full Search and Settings visibly belong to the same
calm Windows 11 / Fluent-adjacent product. Presentation must not regress the
working M22 search path or perceived latency.

## Scope

- a small shared visual resource set for dark, light, and system themes;
- Quick Search header and result-row polish, clear-query action, Full Search and
  Settings access, and source-owned secondary actions;
- Full Search application header, compact common filters, reachable advanced
  filters, sortable supported columns, and Relevance restoration;
- direct Settings access from Full Search;
- polished Settings General, Indexing, and About presentation while preserving
  existing behavior;
- real host visual evidence through WinApp, focused tests, release verification,
  and a bounded perceived-latency guard.

## Frozen mockup interpretations

- Location is omitted: M22 has no location criterion.
- Tray behavior is omitted: it is not an existing persisted setting.
- Kind remains display-only: M22 supports only Relevance, Name, Path, Size, and
  Modified ordering.
- Full Search retains native caption controls, resize, and Snap behavior.

## Out of scope

New search providers, content search, query-language or indexing changes,
Created metadata, path-scope filtering, tray preferences, file-management
actions, service/installer/update work, settings/provider frameworks, and M24
stabilization work.

## Visual checkpoints

1. Quick Search: empty, populated selected result, and context menu.
2. Full Search: populated compact filters, advanced filters, and empty/no-result
   state.
3. Settings: General, Indexing, and About.

Dark is the primary comparison target. Light and System must remain usable.

## Acceptance criteria

- M22 search semantics, shared Core path, lifecycle behavior, and source-owned
  actions remain intact.
- Quick Search is compact and keyboard-first, with calm two-line rows and a
  supported context menu.
- Full Search uses compact filters, preserves all M22 criteria, and presents
  supported sorting through column headers without making Kind sortable.
- Settings opens directly from Full Search and preserves real General, Indexing,
  and About behavior without a Tray behavior setting.
- No Core-to-FileSystem dependency, replacement search engine, broad custom
  chrome, third-party UI framework, or functional scope expansion is added.
- Required real visual evidence, focused tests, the full Release suite, Release
  App build, and bounded latency guard pass before independent QA.

## Verification

Use the canonical WinApp executable on the physical host for semantic UIA
inspection and screenshots. Run focused pure-policy tests, affected Quick/Full/
Settings regressions, the full Release suite, a Release win-x64 App build,
`git diff --check`, dependency-direction inspection, readability inspection,
and the existing bounded render-relevant latency harness.

## Stop conditions

Stop rather than broaden scope if required design references cannot be read,
visual fidelity requires Location, Tray behavior, new search semantics, broad
custom chrome, a third-party UI framework, a Core-to-FileSystem dependency, or
mandatory visual evidence cannot be captured after one supported attempt.
