# Production lifecycle, focus, and resource verification

The final production self-contained `artifacts/m10/publish/self-contained/Quail.exe` was exercised by the dedicated `spikes/m10/harness` entrypoint. It is a narrow adaptation of the M08 resident methodology: it uses real `SendInput`, named-pipe lifecycle events, framework focus plus foreground HWND checks, a post-warm-up resource baseline, and a 120-second hidden-idle CPU sample. It does not call production UI methods directly.

Run environment: normal physical Windows desktop session available to this Codex run; x64 Release harness; Quail default controlled hotkey `Ctrl+Alt+Space`; self-contained publish generated by `scripts/publish-m10.ps1`.

| Scenario | Result | Detail |
| --- | --- | --- |
| Global hotkey/focus | PASS | 100/100 real hotkey → `visible-ready` → valid foreground HWND/query focus → Escape → `hidden` → resident process cycles. |
| Keyboard flow | PASS | 50/50 show → query `quail` → result count > 1 → Down → Up → Enter → Escape → `hidden` cycles. |
| Summon/Escape lifecycle | PASS | 500/500 real hotkey → `visible-ready`/focus → Escape → `hidden`/resident cycles. |
| Hotkey-to-ready latency | PASS | n=100; p50 20.770 ms; p95 26.712 ms; max 32.536 ms; average 21.457 ms. |
| Resource trend | PASS | No crashes or lifecycle failures; USER/GDI/handles do not show a material monotonic growth signal. |
| Hidden idle CPU | PASS | 0.000805% over 120 one-second samples after a 30-second settling period. |

| Checkpoint | Working set (B) | Private bytes (B) | Handles | USER | GDI |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0 post-warm-up | 158,388,224 | 166,727,680 | 1,244 | 48 | 71 |
| 50 | 171,372,544 | 174,538,752 | 1,263 | 52 | 71 |
| 100 | 171,479,040 | 174,542,848 | 1,258 | 52 | 71 |
| 250 | 171,728,896 | 174,747,648 | 1,259 | 52 | 71 |
| 500 | 173,174,784 | 176,214,016 | 1,245 | 50 | 71 |
| 500 settled | 172,331,008 | 175,517,696 | 1,221 | 47 | 71 |

Working set/private bytes rose during resident warm-up and then plateaued. GDI stayed at 71; handles and USER objects ended below baseline. This is bounded warm-up/cache behavior, not the persistent monotonic USER-object growth signal previously observed in the M08 Avalonia candidate.

Raw `metrics.csv`, child diagnostics, stdout, and machine-readable `summary.json` remain under ignored `artifacts/m10/lifecycle-final-production/`; this file is the durable repository summary.
