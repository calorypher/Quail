# Quail 0.3.0 release notes draft

> Release-candidate draft. Do not publish, tag, or upload an asset until the
> documented public code-signing/Smart App Control prerequisite is complete and
> the signed release artifact is rebuilt and verified.

## What is included

Quail 0.3 is a Windows-first, local-first filesystem search application for
Windows 11 x64 and local NTFS volumes. It remains filesystem-only: it searches
indexed file and directory names locally and does not send indexes or queries
to a cloud service.

Since 0.2.0, 0.3 adds:

- continuous filesystem maintenance by the protected LocalSystem
  `QuailMaintenance` service, including restart and normal-downtime catch-up;
- a single service writer for protected machine indexes while ordinary Quick
  Search and Full Search keep direct read-only SQLite snapshots with no search
  service IPC;
- clear fail-closed `RebuildRequired` recovery when NTFS journal continuity
  cannot be proven; Quail never silently performs a full rebuild in that case;
- a unified Settings window for General, Indexing, and About, plus an owned
  per-user Windows-startup option;
- Full Search v1 with a persistent result window, practical filters, sorting,
  Open, Reveal, and Copy path actions;
- Quick Search, Full Search, and Settings usability polish, including native
  caption controls that follow Quail's effective theme;
- measured performance and relevance improvements, including complete
  one/two-character recall, deterministic ranking, and the accepted M16 and
  M18 regression suites.

## Installation and supported transition

- Run `Quail-0.3.0-Setup.exe` with normal Windows elevation after its signed
  public artifact and SHA-256 are published.
- Installation remains fixed at `C:\Program Files\Quail`. The installer checks
  its pinned Microsoft prerequisites and installs only missing .NET 10 Desktop
  Runtime, Windows App Runtime, and x64 Visual C++ Redistributable packages.
- The representative supported transition is released `0.2.0` to `0.3.0` at
  the canonical installation path. It preserves existing ProgramData and
  LocalAppData state. Other historical development-build transitions remain
  uninstall-first.
- The installer registers the LocalSystem maintenance service with a quoted
  Program Files path, normal automatic start, bounded restart recovery, and a
  restrictive service ACL. Uninstall removes the payload, service registration,
  owned Windows-startup entry, and owned PATH entry, but preserves Quail
  ProgramData and user-owned LocalAppData state.

## Security and code-signing status

The M24-C technical RC is unsigned and is **not** suitable as a public release
artifact on devices enforcing Windows Smart App Control. The project must first
adopt a public-trust RSA signing identity and signing workflow. That workflow
must sign the installer, generated uninstaller, and every Quail-owned executable
and DLL in the payload before publishing.

The final signed artifact filename, size, SHA-256, signing identities, and
timestamp verification will be recorded when that external prerequisite is
completed. The exact unsigned technical RC evidence is recorded in
[`M24-C-results.md`](../milestones/M24-C-results.md).

## Known limitations

- Quail indexes local NTFS file and directory names only. It has no content,
  browser, cloud, mail, network-folder, or third-party-plugin source.
- It has no automatic updater, per-user/no-admin deployment mode, Linux build,
  file-history/deleted-item UX, saved searches, preview, or file-manager
  operations.
- A journal discontinuity intentionally requires an administrator-authorized
  Rebuild; Quail does not automatically rebuild an index whose continuity is
  unprovable.
- The Quail-Lab VM does not expose a supported sleep/hibernate path, so its
  existing lifecycle evidence cannot substitute for a physical sleep/resume
  observation. The implementation's restart/catch-up and fail-closed continuity
  evidence remains applicable.

## Release status

publication, and asset upload remain separate owner approvals after independent
